# Web public security gate

Phase 6A adds an explicit fail-closed security boundary without making the existing private backend public.

## Modes

- `MACROVISION_SECURITY_MODE=private` preserves trusted-network development and test behavior.
- `MACROVISION_SECURITY_MODE=public` requires a signed browser session for the private research workspace and the generic `/api/v1/*` browser proxy.
- The FastAPI backend remains private behind the Web/BFF boundary.

## Authentication and authorization

Research login uses a configured username and a PBKDF2-SHA256 password verifier with at least 310,000 iterations. Passwords are never stored in source or in the session. The session is an HMAC-SHA256 signed, eight-hour token stored in an HttpOnly, SameSite=Strict cookie; production cookies are Secure. Roles are explicit and research mutations require the operator role.

## CSRF and origin controls

Research server actions carry the per-session CSRF nonce. Generic browser-proxy mutations require the same nonce in `X-CSRF-Token` and a same-origin `Origin` header. Authentication cookies alone are insufficient to mutate.

## Rate limits

Login attempts are limited to five per ten minutes per trusted client key. Authenticated generic API proxy reads are limited to 120/minute and writes to 20/minute per session/client key. `X-Forwarded-For` is trusted only when `MACROVISION_TRUST_PROXY=1`; production ingress must strip client-supplied forwarding headers and set its own.

The in-process limiter is the application-boundary guard for the single-instance v0.8 deployment. A horizontally scaled deployment must replace it with a shared limiter before adding instances.

## Browser policy

The Web app emits CSP, HSTS in production, frame denial, MIME sniffing denial, a restrictive Permissions Policy, referrer policy, COOP and CORP. The Next.js powered-by header is disabled.

## Remaining gates

Phase 6A does not make internal datasets public. Phase 6B adds reviewed publication eligibility and public-safe read contracts. Phase 6C adds HTTPS/reverse-proxy operations, secret injection, audit logging, backup/restore verification, and production PostgreSQL deployment checks.
